All API requests are authenticated via **API Keys**. Dashboard sessions (key management, Google OAuth login) are handled through Nomba's authentication layer and are not part of this API.

## API Key Authentication

All API requests require an API key via the `X-API-Key` header. The only exceptions are the public checkout endpoints (`/v1/subscription-pages/code/{code}` and `/v1/subscription-pages/code/{code}/checkout`) which are unauthenticated by design.

### Key Types

| Key | Prefix | Use Case | Security |
|-------|--------|----------|----------|
| Public Test | `pk_test_...` | Client-side, sandbox | Safe to expose |
| Secret Test | `sk_test_...` | Server-side, sandbox | Keep private |
| Public Live | `pk_live_...` | Client-side, production | Safe to expose |
| Secret Live | `sk_live_...` | Server-side, production | **Keep extremely private** |

### Usage

```bash
curl -H "X-API-Key: sk_test_abc123..." \
     -H "X-Project-ID: proj_uuid..." \
     {{ API_BASE_URL }}/v1/plans/list
```

<Warning>
Never expose secret keys (`sk_...`) in client-side code, mobile apps, or public repositories.
</Warning>

## Headers Summary

| Header | Required For | Description |
|--------|--------------|-------------|
| `X-API-Key` | All API endpoints | Your secret API key (`sk_test_...` or `sk_live_...`) |
| `X-Project-ID` | Project-scoped endpoints | Your project UUID |

## Key Management

API keys are managed from the **Dashboard → Project Settings**. Keys are scoped to individual projects — each project has its own set of four key slots (`pk_test`, `sk_test`, `pk_live`, `sk_live`).

1. **Regenerate** — Creates a new key; the old one stops working immediately.
2. **Revoke** — Disables a key slot without replacement.

<Note>
Rotating a key immediately invalidates the old one. Update your environment variables and redeploy before revoking.
</Note>

<Note>
You must be a member of a project to manage its keys. Key management is only available through the dashboard UI — there is no public API endpoint.
</Note>
