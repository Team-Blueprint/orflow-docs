description: "Start accepting recurring subscription payments in under 5 minutes."

This guide will walk you through the essential steps to authenticate your requests, define a subscription plan, generate a hosted checkout page for your customers, and verify subscription status.

## Prerequisites

Before getting started, make sure you have:
- An account on [Orflow Dashboard]({{ DASHBOARD_URL }})
- A **Secret Key** (`sk_test_...`) from your Orflow Workspace Settings.
- A HTTP client (like curl, Bruno, or Postman) or a backend server (Node.js, Python, Go, etc.) to run API requests.

---

## Guide

<Steps>
  <Step title="Retrieve your Secret Key">
    Log in to the **Orflow Dashboard**, navigate to your workspace settings, and copy your Secret Key. 
    
    All server-side requests must authenticate by sending this key via the `X-API-Key` header:
    ```bash
    X-API-Key: sk_test_your_secret_key
    ```
    
    <Warning>
      Keep your Secret Keys (`sk_test_...` and `sk_live_...`) strictly confidential. Never expose them on frontend clients, public repositories, or mobile applications.
    </Warning>
  </Step>

  <Step title="Create your first subscription Plan">
    To start accepting billing cycles, create a plan. Plans specify how much and how often a customer should be charged.
    
    Send a `POST` request to `/v1/plans/create` to create a plan with a major unit amount (e.g., `29.99` for $29.99):

    ```bash
    curl -X POST {{ API_BASE_URL }}/v1/plans/create \
      -H "X-API-Key: sk_test_your_secret_key" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "Pro Plan",
        "description": "Access to advanced developer features",
        "amount": 29.99,
        "currency": "USD",
        "interval": "monthly"
      }'
    ```

    The response returns a unique `id` for your plan (e.g., `plan_abc123`). Keep track of this ID for the next step.
  </Step>

  <Step title="Create a Subscription Page">
    A subscription page is a shareable landing page that lets customers sign up and pay. Create one linked to your plan:

    ```bash
    curl -X POST {{ API_BASE_URL }}/v1/subscription-pages/create \
      -H "X-API-Key: sk_test_your_secret_key" \
      -H "X-Project-ID: your_project_uuid" \
      -H "Content-Type: application/json" \
      -d '{
        "plan_id": "plan_abc123"
      }'
    ```

    The response includes a unique `code` (e.g. `abc123xy`) that forms the public checkout URL:

    ```json
    {
      "id": "page_uuid",
      "code": "abc123xy",
      "plan_id": "plan_abc123",
      "is_active": true,
      "is_test": true
    }
    ```

    Share the URL `{{ SITE_URL }}/pay/abc123xy` with your customer. Orflow renders a branded payment page that collects the customer's name, email, and card details.
  </Step>

  <Step title="Customer Completes Checkout">
    When the customer submits the payment form, your frontend calls the public checkout endpoint:

    ```bash
    curl -X POST {{ API_BASE_URL }}/v1/subscription-pages/code/abc123xy/checkout \
      -H "Content-Type: application/json" \
      -d '{
        "name": "Jane Doe",
        "email": "jane@example.com"
      }'
    ```

    The response returns a Nomba checkout link for card payment:

    ```json
    {
      "checkout_link": "https://nomba-checkout-url",
      "order_reference": "ORD_xyz789"
    }
    ```

    Redirect the customer to this link. Nomba handles card validation, tokenization, and payment collection. On success, Orflow creates the subscription and schedules recurring billing.
  </Step>

  <Step title="Listen for billing events via Webhooks">
    Once the customer completes their checkout payment, Orflow tokenizes their payment method and schedules subsequent recurring bills.
    
    Your server can listen for webhooks to instantly update your user's entitlement:
    
    - `subscription.activated`: Dispatched when a subscription becomes active after first payment.
    - `invoice.payment_failed`: Dispatched if an auto-renewal charge fails (triggers dunning retries).
    - `subscription.canceled`: Dispatched when a subscription is deactivated.
  </Step>
</Steps>
