## Base URL

All API requests use a single base URL:

```
{{ API_BASE_URL }}
```

## API Keys

Orflow provides four API key slots per tenant.

| Key | Prefix | Visibility | Use Case |
|-----|--------|------------|----------|
| Public Test | `pk_test_...` | Publishable | Client-side SDK, development |
| Secret Test | `sk_test_...` | Secret | Server-side, development |
| Public Live | `pk_live_...` | Publishable | Client-side SDK, production |
| Secret Live | `sk_live_...` | Secret | Server-side, production |

<Warning>
Never use live API keys in development. Never commit secret keys to version control.
</Warning>

## Making API Calls

```bash
curl -H "X-API-Key: sk_test_..." \
     -H "X-Project-ID: your_project_uuid" \
     {{ API_BASE_URL }}/v1/plans/list
```

## Required Headers

| Header | Required | Description |
|--------|----------|-------------|
| `X-API-Key` | Yes | Your API key (`sk_test_...` or `sk_live_...`) |
| `X-Project-ID` | For most project-scoped endpoints | Your project UUID |

<Note>
`POST /v1/subscriptions/create` does **not** require `X-Project-ID`. If `customer_id` is omitted, the project is resolved from the plan. If `customer_id` is provided, the customer's existing project is used.
</Note>

## Environment Per Project

The Orflow Dashboard stores the sandbox/live environment toggle per project. Each project maintains its own environment state in localStorage (`orflow_env_{projectId}`). Switching between projects automatically loads the correct environment setting.

You can change the environment in **Project Settings** → **Environment** toggle.

## Environment Variables

Store keys securely in your environment:

```bash
# .env.local
ORFLOW_API_KEY=sk_test_abc123...
ORFLOW_PROJECT_ID=proj_abc123...
ORFLOW_BASE_URL={{ API_BASE_URL }}
```

<Warning>
Use separate `.env` files per environment. Never commit them to git.
</Warning>
